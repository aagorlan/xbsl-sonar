# xbsl-sonar

Проверки **безопасности и производительности** кода XBSL (1С:Предприятие.Элемент):
то, чего не ловит сборка. Синтаксис здесь не проверяется — это делает сама платформа.

- Разбор XBSL — движок [keyfire/xbsl](https://github.com/keyfire/xbsl) (MIT), закреплённой
  версией; его собственные правила в анализе не участвуют, работают только правила отсюда.
- Свод проверок — ISO/IEC 5055 (CISQ: безопасность и эффективность) и OWASP Top 10 2021;
  у каждой проверки код `ПР-NN` и пункт CWE.
- Работает **сам по себе** (находки в консоли и файлом, код возврата для CI) и **с SonarQube**
  через плагин [sonar-bsl-plugin-community](https://github.com/1c-syntax/sonar-bsl-plugin-community).

## Проверки

| Код | Что ловит | CWE |
|---|---|---|
| ПР-01 | метод `@НаСервере @ДоступноСКлиента` принимает ссылку на объект и открывает привилегированный контекст без сверки с текущим пользователем. Сверка — вызов метода, читающего текущего пользователя (набор собирается по проверяемому коду и замыкается по вызовам), `ТекущийПользователь` в условии `если` или `КонтрольДоступа.ПроверитьПраво`/`ЕстьПраво` до повышения прав. Не находка — метод без параметров-ссылок или без повышения прав | CWE-639, 862, 863 |
| ПР-03 | точка без аутентификации вне согласованного перечня: в YAML — `РежимАутентификации: НеАутентифицированный`, право `РазрешеноВсем` (и `Вызов:` HTTP-сервиса), элемент `HttpСервис`; в XBSL — `КонтекстДоступа.Привилегированный()` в модуле элемента для неаутентифицированных (по паре `.yaml`). Не находка — точка из перечня периметра (`--perimeter`) или с пометкой `анализ:периметр`. Форма, открытая из приложения гостя, сама по себе находкой не считается: режим аутентификации задаётся у приложения | CWE-732, 284, 276 |
| ПР-04 | разметка из данных выполняется в браузере без очистки: в YAML — `КонтейнерHtml` с `БезопасныйРежим: Ложь`, у которого `Содержимое` — выражение, а не ресурс; в XBSL — присваивание `….Имя.Содержимое` такому контейнеру не ресурсом; в ресурсе `.html`/`.js` — `.innerHTML =` не литералом и не из констант скрипта вне функции очистки (`--sanitizers`, по умолчанию `очистить`). Не находка — безопасный режим по умолчанию; метод пары `.xbsl`, отдающий ресурс без подстановок или с подстановкой, где экранирован `<` (`.Заменить("<", "\\u003c")`) | CWE-79 |
| ПР-02 | действие, которое интерфейс показывает только администратору, без проверки на сервере: в YAML компонента элемент с `Видимость`/`Доступность` про администратора (`=ДанныеПользователя.Администратор`, `=Администратор`, `ЭтоАдминистратор()`), а внутри него — обработчик, который через методы формы доходит до метода `@НаСервере @ДоступноСКлиента`, пишущего (`Записать`, `Удалить`) в привилегированном контексте сам или через вызываемые, без сверки с текущим пользователем (как в ПР-01); или поле `Значение: =Объект.Реквизит`, когда объект вправе менять не только администратор (`Изменение`/`ПоУмолчанию` указано и не `РазрешеноАдминистраторам`), а `ПередЗаписью` объекта реквизит со сверкой не проверяет — поля одного элемента одной находкой. Не находка — запись по правам объекта, без повышения; проверка в серверном методе или в вызываемых; форма, открытая из такого элемента (её методы — ПР-01) | CWE-285, 424 |
| ПР-05 | повышение прав с клиента без сверки: метод `@НаСервере @ДоступноСКлиента` без параметров-ссылок открывает `КонтекстДоступа.Привилегированный()` или `ГрупповаяОперация.Начать(…, ПривилегированныйРежим = Истина)` без сверки с текущим пользователем (как в ПР-01); `Привилегированный()` не в инструкции `исп` — контекст переживает строку — в любом методе. Не находка — метод с параметром-ссылкой (его проверяет ПР-01), серверный метод без доступа с клиента, `исп` с именем | CWE-269 |
| ПР-06 | секрет строкой в коде: строковый литерал присваивается или передаётся именованным аргументом туда, чьё имя говорит о секрете (`Токен`, `Пароль`, `Секрет`, `КлючAPI`, `token`, `password`, `secret`, `apikey` в любом месте имени), кладётся в соответствие под таким ключом-строкой; литерал вида токена Telegram-бота или заголовка `Bearer`/`Basic` где угодно; в YAML — `ЗначениеПоУмолчанию` реквизита с таким именем или типа `СекретПриложения`. Секрет — от 8 знаков, без пробелов, кириллицы и `%`. Не находка — литерал при имени не про секрет (`Пользователь = "AUTH_TOKEN"`), имя поля протокола с переменной в значении, подписи и шаблоны адресов, пустые и короткие строки | CWE-798 |
| ПР-15 | обращение к данным в цикле: запрос в теле цикла `для`; вызов серверного метода того же модуля из цикла клиентского метода. Не находка — запрос в заголовке цикла, запрос в цикле `пока` (порции, уровни дерева), запись объектов в цикле | CWE-1050 |
| ПР-16 | повторяющийся таймер клиента (`ПодключитьОбработчикТаймера` без однократности) с интервалом короче порога (`--min-period`, по умолчанию 60 с), обработчик которого безусловно вызывает серверный метод — сам или через методы модуля и проекта. Не находка — однократный таймер, интервал от порога, интервал не литералом, вызов сервера только в теле `если`/`выбор` (по изменению); вызов в условии `если` — находка | CWE-1060 |
| ПР-17 | обращение к серверу при каждой перерисовке формы: свойство-выражение компонента в YAML (`Значение: =Метод()`, `Видимость: =…`), метод которого доходит до сервера или базы — серверный или с `Запрос{…}`, сам или через методы проекта (в строке списка — на каждую строку); обработчик компонента (`@Обработчик`), где запросов и вызовов таких методов больше порога (`--max-accesses`, по умолчанию 3). Не находка — выражение без вызова метода, `ЗначениеПоУмолчанию` свойства (считается один раз), вычисление на клиенте | CWE-1073 |

Полные описания — `xbsl-sonar rules-file` (тот же текст видит SonarQube).

## Данные о языке

Движку нужны ключевые слова XBSL. Их автор извлекает из дистрибутива платформы;
здесь они строятся при каждом запуске из **выгрузки справки 1С:Элемент**, которая лежит
у вас в проекте (`--help-dir`, каталог с `topics/`; нужна страница
`topics/keywords/index.md`). Ни справка, ни данные из неё в этом репозитории не хранятся:
справка охраняется правом 1С.

## Самостоятельный запуск (без SonarQube)

Нужен Python 3.10+.

```sh
python3 -m venv .venv
.venv/bin/pip install "xbsl-sonar @ git+https://github.com/aagorlan/xbsl-sonar@v0.9.0"

.venv/bin/xbsl-sonar check <каталог проекта> --help-dir <выгрузка справки> \
    --json находки.json
```

Что получается:

- в консоли — находки в виде `файл:строка:столбец: [ПР-NN] сообщение` и итог;
- `--json` — те же находки файлом: правило, место, сообщение, исключение;
- **код возврата**: `0` — находок без исключения нет, `1` — есть, `2` — ошибка запуска.
  Этого достаточно, чтобы ронять проверку в любом CI.

Полезное:

- `--rules ПР-01,ПР-15` — только перечисленные правила;
- `xbsl-sonar data --help-dir <справка> --out <каталог>` — собрать данные о языке один раз
  и дальше запускать `check --data-dir <каталог>`.

### Периметр (ПР-03)

Точка без аутентификации — не ошибка, а решение: её открывают намеренно. Поэтому находка
ПР-03 закрывается не исключением с долгом, а записью в **перечне периметра** — текстовом
файле проекта, который передаётся параметром `--perimeter`:

```text
# путь: Ключ — почему открыто
IT/Проект/Гость/Лендинг.yaml: РежимАутентификации — лендинг для гостей
IT/Проект/Обмен/Сервис.yaml: Вызов — приём сообщений, секрет в адресе
```

Запись закрывает все находки с этим ключом в этом файле. В коде XBSL точку можно отметить
и на месте — `// анализ:периметр — причина` в строке находки или строкой выше. Новая точка
без записи роняет проверку: открыть периметр незаметно для проверяющего PR нельзя.

### Согласованные находки (ПР-02, ПР-04, ПР-05, ПР-16, ПР-17)

Разметка, которую правило не может проверить до конца (экранирование в другом модуле,
число из своего сервиса), известный опрос сервера таймером, выражение формы, которое
ходит на сервер, поле администратора без проверки при записи и повышение прав
без сверки, которое делает только безопасное, — если их переделку
отложили, — закрываются записью в **перечне согласованных находок**
(`--agreed`), а не исключением с долгом: пометку в YAML не поставить — комментариев там нет.

```text
# путь: ПР-04 Ключ — почему безопасно
IT/Проект/Чат/Окно.yaml: ПР-04 КонтейнерHtml Переписка — параметры экранируют «<» при подстановке
IT/Проект/Лента/Форма.xbsl: ПР-16 Таймер ОбновитьСчётчики — опрос раз в 10 с, переделка в ТД-7
```

Ключ — начало сообщения находки до двоеточия. Причина обязательна.

### Исключения

Находку, которую решено не исправлять, отмечают в коде — в строке находки или строкой выше:

```xbsl
// анализ:исключение ПР-15 ТД-12 — разовая обработка десятка записей
знч Настройки = Запрос{...}.Выполнить()
```

После кода правила — ссылка на запись, где решение обосновано (например, пункт
технического долга), после тире — причина. Находка под пометкой не роняет проверку,
но остаётся в отчёте с этой ссылкой. Пометка для другого правила не действует.

## Запуск с SonarQube

Сервер разворачивается по [техническому заданию](docs/развёртывание.md): SonarQube
Community Build, плагин веток и плагин 1С с описаниями правил отсюда.

### В GitHub Actions

Готовый процесс — `.github/workflows/analysis.yml`, вызывается из вашего репозитория:

```yaml
name: Анализ кода
on:
  pull_request:
  workflow_dispatch:
jobs:
  analysis:
    uses: aagorlan/xbsl-sonar/.github/workflows/analysis.yml@v0.9.0
    with:
      version: v0.9.0
      paths: src
      help-dir: docs/vendor
      perimeter: docs/периметр.txt         # перечень для ПР-03; можно не задавать
      sonar-url: ${{ vars.SONAR_URL }}      # пусто — без SonarQube
      runs-on: ubuntu-latest               # или self-hosted
    secrets:
      sonar-token: ${{ secrets.SONAR_TOKEN }}
```

Процесс ставит xbsl-sonar, проверяет код, пишет находки в сводку запуска, отправляет
отчёт в SonarQube (для PR — как анализ PR, иначе — как анализ ветки) и краснеет,
если есть находка без пометки исключения. Сканер SonarQube скачивается со встроенной
Java — ставить её на исполнитель не нужно. На своём исполнителе нужны Python 3.10+
с модулем `venv`, `curl` и `unzip`.

### Руками

Рядом с кодом — `sonar-project.properties`:

```properties
sonar.projectKey=<ключ проекта в SonarQube>
sonar.sources=<каталог проекта>
sonar.sourceEncoding=UTF-8
# Файлы XBSL отдаются плагину 1С
sonar.bsl.file.suffixes=.xbsl
```

Затем:

```sh
xbsl-sonar check <каталог проекта> --help-dir <справка> --bsl-report .xbsl-sonar/bsl-report.json
sonar-scanner \
  -Dsonar.host.url=<адрес SonarQube> \
  -Dsonar.token=<токен анализа> \
  -Dsonar.branch.name=<ветка> \
  -Dsonar.bsl.languageserver.enabled=false \
  -Dsonar.bsl.languageserver.reportPaths=.xbsl-sonar/bsl-report.json \
  -Dsonar.bsl.universal.createExternalIssues=true
```

- `languageserver.enabled=false` — встроенный анализатор BSL выключен: он рассчитан
  на язык 1С:Предприятия 8 и XBSL не разбирает;
- отчёт `--bsl-report` — в формате BSL Language Server, находки в нём с `source: universal-rules`
  и кодом правила `PR-NN` (латиницей — ключ правила на сервере);
- `universal.createExternalIssues=true` — находка правила, которого сервер ещё не знает
  (описания не обновлены), всё равно появится как внешняя.

### Описания правил на сервере

```sh
xbsl-sonar rules-file --out universal.json
```

Файл кладётся на сервер, путь к нему — в настройку сервера
`sonar.bsl.universal.rulesPaths`, и сервер перезапускается: плагин читает описания
при старте. Делать это при каждой новой версии xbsl-sonar, где появились проверки.
Правила с описанием плагин сам собирает во встроенный профиль качества
«Universal - full check» — его и назначить проекту.

## Разработка

```sh
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/python -m pytest
```

Новая проверка — одно правило в `xbsl_sonar/rules.py` (регистрация `@rule` движка,
описание в `RULES`), положительные и отрицательные примеры в `tests/`, строка в таблице
проверок выше и новая версия: подъём `__version__` в `xbsl_sonar/__init__.py` — метку
`v<версия>` и выпуск на странице Releases после вливания в `main` ставит процесс «Выпуск». Ворот правила: ноль ложных находок на рабочем коде.
