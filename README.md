# xbsl-sonar

Проверки **безопасности и производительности** кода XBSL (1С:Предприятие.Элемент):
то, чего не ловит сборка. Синтаксис здесь не проверяется — это делает сама платформа.

- Разбор XBSL — движок [keyfire/xbsl](https://github.com/keyfire/xbsl) (MIT), закреплённой
  версией; его собственные правила в анализе не участвуют, работают только правила отсюда.
- Свод проверок — ISO/IEC 5055 (CISQ: безопасность и эффективность) и OWASP Top 10 2021;
  у каждой проверки код `ПР-NN` и пункт CWE.
- Работает **сам по себе** (находки в консоли и файлом, код возврата для CI) и **с SonarQube**
  через плагин [sonar-bsl-plugin-community](https://github.com/1c-syntax/sonar-bsl-plugin-community).

## Проверки

| Код | Что ловит | CWE |
|---|---|---|
| ПР-15 | обращение к данным в цикле: запрос в теле цикла `для`; вызов серверного метода того же модуля из цикла клиентского метода. Не находка — запрос в заголовке цикла, запрос в цикле `пока` (порции, уровни дерева), запись объектов в цикле | CWE-1050 |

Полные описания — `xbsl-sonar rules-file` (тот же текст видит SonarQube).

## Данные о языке

Движку нужны ключевые слова XBSL. Их автор извлекает из дистрибутива платформы;
здесь они строятся при каждом запуске из **выгрузки справки 1С:Элемент**, которая лежит
у вас в проекте (`--help-dir`, каталог с `topics/`; нужна страница
`topics/keywords/index.md`). Ни справка, ни данные из неё в этом репозитории не хранятся:
справка охраняется правом 1С.

## Самостоятельный запуск (без SonarQube)

Нужен Python 3.10+.

```sh
python3 -m venv .venv
.venv/bin/pip install "xbsl-sonar @ git+https://github.com/aagorlan/xbsl-sonar@v0.1.0"

.venv/bin/xbsl-sonar check <каталог проекта> --help-dir <выгрузка справки> \
    --json находки.json
```

Что получается:

- в консоли — находки в виде `файл:строка:столбец: [ПР-NN] сообщение` и итог;
- `--json` — те же находки файлом: правило, место, сообщение, исключение;
- **код возврата**: `0` — находок без исключения нет, `1` — есть, `2` — ошибка запуска.
  Этого достаточно, чтобы ронять проверку в любом CI.

Полезное:

- `--rules ПР-15` — только перечисленные правила;
- `xbsl-sonar data --help-dir <справка> --out <каталог>` — собрать данные о языке один раз
  и дальше запускать `check --data-dir <каталог>`.

### Исключения

Находку, которую решено не исправлять, отмечают в коде — в строке находки или строкой выше:

```xbsl
// анализ:исключение ПР-15 ТД-12 — разовая обработка десятка записей
знч Настройки = Запрос{...}.Выполнить()
```

После кода правила — ссылка на запись, где решение обосновано (например, пункт
технического долга), после тире — причина. Находка под пометкой не роняет проверку,
но остаётся в отчёте с этой ссылкой. Пометка для другого правила не действует.

## Запуск с SonarQube

Сервер разворачивается по [техническому заданию](docs/развёртывание.md): SonarQube
Community Build, плагин веток и плагин 1С с описаниями правил отсюда.

### В GitHub Actions

Готовый процесс — `.github/workflows/analysis.yml`, вызывается из вашего репозитория:

```yaml
name: Анализ кода
on:
  pull_request:
  workflow_dispatch:
jobs:
  analysis:
    uses: aagorlan/xbsl-sonar/.github/workflows/analysis.yml@v0.1.0
    with:
      version: v0.1.0
      paths: src
      help-dir: docs/vendor
      sonar-url: ${{ vars.SONAR_URL }}      # пусто — без SonarQube
      runs-on: ubuntu-latest               # или self-hosted
    secrets:
      sonar-token: ${{ secrets.SONAR_TOKEN }}
```

Процесс ставит xbsl-sonar, проверяет код, пишет находки в сводку запуска, отправляет
отчёт в SonarQube (для PR — как анализ PR, иначе — как анализ ветки) и краснеет,
если есть находка без пометки исключения. Сканер SonarQube скачивается со встроенной
Java — ставить её на исполнитель не нужно. На своём исполнителе нужны Python 3.10+
с модулем `venv`, `curl` и `unzip`.

### Руками

Рядом с кодом — `sonar-project.properties`:

```properties
sonar.projectKey=<ключ проекта в SonarQube>
sonar.sources=<каталог проекта>
sonar.sourceEncoding=UTF-8
# Файлы XBSL отдаются плагину 1С
sonar.bsl.file.suffixes=.xbsl
```

Затем:

```sh
xbsl-sonar check <каталог проекта> --help-dir <справка> --bsl-report .xbsl-sonar/bsl-report.json
sonar-scanner \
  -Dsonar.host.url=<адрес SonarQube> \
  -Dsonar.token=<токен анализа> \
  -Dsonar.branch.name=<ветка> \
  -Dsonar.bsl.languageserver.enabled=false \
  -Dsonar.bsl.languageserver.reportPaths=.xbsl-sonar/bsl-report.json \
  -Dsonar.bsl.universal.createExternalIssues=true
```

- `languageserver.enabled=false` — встроенный анализатор BSL выключен: он рассчитан
  на язык 1С:Предприятия 8 и XBSL не разбирает;
- отчёт `--bsl-report` — в формате BSL Language Server, находки в нём с `source: universal`
  и кодом правила `PR-NN` (латиницей — ключ правила на сервере);
- `universal.createExternalIssues=true` — находка правила, которого сервер ещё не знает
  (описания не обновлены), всё равно появится как внешняя.

### Описания правил на сервере

```sh
xbsl-sonar rules-file --out universal.json
```

Файл кладётся на сервер, путь к нему — в настройку сервера
`sonar.bsl.universal.rulesPaths`, и сервер перезапускается: плагин читает описания
при старте. Делать это при каждой новой версии xbsl-sonar, где появились проверки.
Правила с описанием плагин сам собирает во встроенный профиль качества
«Universal - full check» — его и назначить проекту.

## Разработка

```sh
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/python -m pytest
```

Новая проверка — одно правило в `xbsl_sonar/rules.py` (регистрация `@rule` движка,
описание в `RULES`), положительные и отрицательные примеры в `tests/`, строка в таблице
проверок выше и новая версия. Ворот правила: ноль ложных находок на рабочем коде.
